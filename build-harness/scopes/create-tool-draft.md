# create-tool-draft scope

tool-calling-poc harness. A short loop for adding or changing one Agent tool
on an existing Agent: write the tool contract, implement it, and prove V1~V6
with eval cases. Repeat the loop per tool.

## Why these stages

- **Initialization** (3): required by every scope.
- **Reverse Engineering**: brownfield context. On a rerun it can reuse a
  current code knowledge base, so later loops stay short.
- **Requirements Analysis**: the tool contract. The `requirements.md` template
  carries the V1~V6 sections and the `json tool-contract` block.
- **Code Generation**: tools, instructions, Runner limits, and the
  deterministic eval tests. The `tool-contract` sensor blocks the gate until
  the code matches the contract.
- **Build and Test**: runs tests and live-model eval. The `tool-eval` sensor
  blocks the gate until every criterion has passing cases and the summary
  reports them.

Everything else is SKIP: Ideation (the intent is a tool, already decided),
user stories and mockups (no new screen), domain and unit design (one tool
per loop, no Unit DAG), and the deploy tail (draft, not release).

## Ceremony

- `sensors: on` is required: the two blocking sensors only run with it.
- `review_cap: none`, `plan_approval: off`, `summary_confirmation: off`, and
  `learnings: off` trade review depth for speed. Raise `review_cap` to
  `advisory` when description quality needs a reviewer pass.
